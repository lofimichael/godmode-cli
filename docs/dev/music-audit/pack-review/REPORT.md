# Independent Music Pack experience review

**Rating: 8.5/10.** The library, search, collection and queue experience is strong and feels like a finished terminal product. I found no functional blocker in the exercised paths. The remaining gap is the pack's first-use experience: jingles work immediately, but the player directs a new user entirely toward the larger synth-and-tracks setup without making that immediate feature discoverable there.

This was an independent black-box review of the actual CLI. I read no implementation or prior review reports. The supplied PTY/recorder code was read solely to drive and capture the terminal. Product files were not edited. Captures used real 80×24 and 40×18 PTYs and the supplied CSI-Z-aware screen model. All commands used a fresh private HOME and GODMODE_HOME, with no real Godmode keys, profile, account or license data. The existing 1,620-track source library was read-only. Playback was muted: jingle play used --volume 0, and music volume was set to 0 before the first music play. No judgment about audible musical quality is included.

## What worked

1. **Opt-in and cancellation:** The initial card explains the player/library/queue, local synth, original jingles, .ootrs requirement, optionality and removal. It fits both sizes without crowding or lost controls. Escape exits successfully. After the first cancellation, the isolated home contained no files. Evidence: `01-initial-card-80.png`, `03-initial-card-40.png`, actions/results logs.
2. **Installation:** Local installation using `music install --file PACK --sha256 HASH` succeeded. Its output immediately gives `godmode jingle play` and the tracks setup command. Public download installation was intentionally not exercised because this pack has not been released.
3. **Jingles:** `help jingle` clearly explains that jingles need mpv but neither synth setup nor local tracks. `jingle list` returned ready/success/attention. `jingle play ready --volume 0` succeeded before synth setup.
4. **Setup guidance:** The empty library shows a scrolling guide, a concrete quoted-path example, dependencies, compiler setup, subfolder/collection behavior and reload instructions. Setup with the existing read-only library completed in 12.458 seconds and reported 1,620 local tracks. Pressing R in the already-open 40-column player populated the library. Evidence: `04-installed-library-80.png`, `07-setup-guidance-lower-80.png`, `08-setup-guidance-bottom-80.png`, `09-setup-guide-40.png`, `10-library-40.png`.
5. **Search safety and collection discovery:** Typing `/ocarina` showed 16 live matches. Enter focused results without starting audio. The focused results visibly expose c collection and A add collection at 80 columns; the 40-column footer exposes c. Searching a collection name also worked (`legend of zelda ocarina`, 6 matches). Evidence: `12-search-typing-80.png`, `13-search-results-80.png`, `26-search-results-40.png`, `31-collection-search-40.png`.
6. **Full collection from a matching track:** From Rocky's Message [Ocarina], i showed the full title, Pocky & Rocky collection, and explicit c/A instructions. c opened both songs in that collection, including the Oboe version which did not match the search, while preserving the selected Ocarina track. Escape returned to details, then to the original search and selection. This also worked at 40 columns. Evidence: `14-track-details-80.png` through `17-back-from-search-80.png`, `27-track-details-40.png`, `28-collection-40.png`.
7. **Queue:** A from the filtered result appended both collection tracks; Tab displayed the two-track queue. Queue details describe Enter's queue-specific behavior. Escape from details restored the queue; Escape again restored the original search. Appending from details with a gave a useful 'Tab to inspect' status and Tab actually opened the queue. Evidence: `18-append-full-collection-80.png` through `21-queue-back-search-80.png`, `33-append-from-details-40.png`, `34-tab-from-details-40.png`.
8. **Quit versus stop:** With volume 0, Enter on a queued track showed preparation. q closed the view and explicitly printed `Music keeps playing. Stop it with: godmode music stop`. A separate status command confirmed actual playback with mpv audio clock and volume 0. Relaunch at 40×18 showed an advancing 0:17/3:00 position. x stopped playback, kept the queue and showed that outcome. A separate status command confirmed stopped. Evidence: `22-play-muted-80.png` through `25-stopped-40.png` and results log.
9. **Removal and reinstall:** Removal reported that pack/runtime/cache were removed and source songs retained. Status then reported not installed/nothing playing; opening music returned to the opt-in card. Reinstall with the same verified local file succeeded and returned to the empty setup guide, with a fresh empty queue. Hashes of all 1,620 source file contents and relative paths were identical before and after removal. Final cleanup stopped music and removed the isolated pack again. Evidence: `35-after-removal-80.png`, `36-reinstalled-setup-guide-40.png`, source-before/after JSON files.
10. **Visual quality:** Clear selection, good spacing and restrained purple/cyan identity at both sizes. The 40-column player prioritizes titles and uses details for the full collection/title. I visually inspected PNGs in addition to reading reconstructed screen text.

## Remaining improvements

- **Make jingles visible in the empty player.** The opt-in card promises original jingles and the installer gives their command, but the actual empty player is entirely a setup guide for .ootrs and synth dependencies. Neither the guide nor the player-key help showed a jingle path. Add a short 'Try a jingle now' command or action to that empty state, ideally before the longer setup work. This is a concrete discoverability gap, not broken jingle functionality.
- **Wrap the small-terminal help descriptions.** At 40×18 the help truncates lines such as `Enter Open collection / play tra…`, `Enter/Tab Finish search; focus resul…`, and `godmode music stop Stops from any sh…`. Controls remain legible and usable, so this is polish rather than a blocker. Setup prose and selected details already have a better compact presentation.

No functional release blocker was observed within this review's scope. I would call the core library/player experience great for a terminal user who has a local sequence collection. I would still polish the immediate post-install path before calling the whole pack onboarding great.

## Evidence and boundaries

There are 36 PNG captures and matching text screens, `actions.jsonl`, `results.jsonl`, a reusable review driver, `receipt.json`, and before/after source-content hashes in this directory. The driver imported only the allowed terminal harness/recorder. The lone transient `1u` visible in some exit-screen reconstructions was not treated as a product UI finding; the supplied recorder does not fully model terminal keyboard-protocol teardown.

This review did not test public download/release hosting, listen to audio, validate every track or instrument, test every transport command, or prove that an entirely unprepared machine has the stated dependencies. Setup was tested on this machine with its existing tools, under an isolated user home. Reinstallation itself was verified; the synth was not rebuilt a second time after removal. Source integrity hashes bracket removal, not the earlier setup operation; the reviewer issued no writes to the source directory.
